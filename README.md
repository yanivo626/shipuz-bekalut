# שיפוץ בקלות — גרסת אינטרנט לאלפי משתמשים

זו הגרסה ה**אמיתית** של האפליקציה: כל מי שנכנס נרשם עם אימייל+סיסמה
משלו/ה, ורואה **רק** את הפרויקטים שלו/ה. הנתונים נשמרים במסד נתונים אמיתי
(לא בתוך קלוד), והתמונות בקבצים אמיתיים — לא בטקסט מקודד.

## מה השתנה מהגרסה הקודמת

| | גרסת קלוד (הקודמת) | גרסה זו |
|---|---|---|
| מי רואה מה | רק את/ה, בתוך השיחה בקלוד | כל משתמש/ת רואה רק את שלו/ה |
| איפה נשמר | `window.storage` (מנגנון פנימי של קלוד) | Postgres אמיתי (Supabase) |
| תמונות | טקסט מקודד (עד 5MB לפריט) | קבצים אמיתיים, בלי הגבלה כזו |
| הרשמה | אין (זו/הו את) | אימייל + סיסמה, כל מבקר/ת בנפרד |
| היכן רץ | רק בתוך קלוד | אתר אמיתי, בכל דפדפן |

## שלב 1 — הקמת Supabase (חינם עד היקף משמעותי)

1. גשי ל-https://supabase.com → New Project (חשבון חינמי מספיק להתחלה).
2. תוך כדי היצירה, שמרי את **Database Password** שתבחרי — לא נצטרך אותה
   ישירות אבל טוב לשמור.
3. אחרי שהפרויקט מוכן (דקה-שתיים): **SQL Editor** בתפריט הצד → **New query**
   → הדביקי את **כל** התוכן של `supabase/schema.sql` מהתיקייה הזו → **Run**.
   זה יוצר את טבלת הפרויקטים, את מדיניות האבטחה (RLS), ואת מקום אחסון
   התמונות.
4. **Project Settings → API** → תעתיקי משם שני ערכים:
   - `Project URL`
   - `anon public` key (לא ה-`service_role`, זה חשוב — ה-anon key בטוח
     לחשיפה בצד הלקוח, ה-service_role לא).

## שלב 2 — הרצה מקומית לבדיקה

```bash
cd webapp
npm install
cp .env.example .env
# ערכי את .env עם ה-URL וה-anon key מהשלב הקודם
npm run dev
```

יפתח על `http://localhost:5173`. נסי להירשם עם אימייל שלך, ליצור פרויקט,
ולוודא שהכול עובד לפני שממשיכים לפריסה.

**הערה על אימות אימייל:** כברירת מחדל Supabase שולח מייל אימות בהרשמה.
אם רוצים לדלג על זה בזמן הבדיקות: **Authentication → Providers → Email**
→ כבי את "Confirm email" זמנית (אפשר להדליק בחזרה לפני שמפרסמים).

## שלב 3 — פריסה לאוויר (Vercel, חינמי)

1. העלי את תיקיית `webapp` ל-GitHub (repo חדש).
2. גשי ל-https://vercel.com → **New Project** → חברי את ה-repo.
3. Framework Preset: **Vite** (יזוהה אוטומטית).
4. **חשוב:** במסך ה-Environment Variables, הוסיפי:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
   (אותם ערכים מ-`.env` שלך).
5. Deploy. תוך דקה תקבלי כתובת אמיתית (`https://your-app.vercel.app`)
   שכל מי שתרצי יכול/ה להיכנס אליה ולהירשם עצמאית.

## מה קורה אם משתמש/ת אחד/ת רואה נתונים של אחר/ת?

זה בדיוק מה ש-**Row Level Security** (חלק מ-`schema.sql`) מונע — כל שאילתה
למסד הנתונים מסוננת אוטומטית לפי מי מחובר/ת. גם אם מישהו ינסה "לרמות"
דרך כלי פיתוח בדפדפן, השרת של Supabase עצמו חוסם גישה לשורות שלא שייכות
לו/ה. זה חלק מהותי מהאבטחה, ולכן לא כדאי לגעת במדיניות ה-RLS ב-SQL בלי
להבין את ההשלכות.

## גבולות ועלויות ל"אלפי משתמשים"

- **התוכנית החינמית של Supabase** כוללת 500MB מסד נתונים ו-1GB אחסון
  קבצים — מספיק להתחלה טובה, אבל עם אלפי משתמשים ותמונות תגיעו לתקרה
  וצריך לשדרג לתוכנית בתשלום (מתחילה בכ-25$/חודש).
- **Vercel** בתוכנית החינמית מספיקה כמעט תמיד לאתר כזה (לא שרת, רק קבצים
  סטטיים שנטענים לדפדפן).
- מומלץ להוסיף בעתיד: הגבלת קצב הרשמות (מונע ספאם), ואולי תשלום/מנוי
  ברגע שהמוצר מוכן לגמרי לשוק.

## מה עדיין לא כלול (להמשך)

- איפוס סיסמה שנשכחה (Supabase תומך בזה, רק צריך להוסיף מסך).
- התחברות עם Google/Apple (גם נתמך ב-Supabase, תוספת קטנה).
- עמוד נחיתה שיווקי לפני ההרשמה (כרגע נכנסים ישר למסך התחברות).
